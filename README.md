# Restaurant Booking System

Веб-приложение для бронирования столиков в ресторане. Клиент выбирает столик
на интерактивной карте зала, бронирует его на нужное время, администратор
подтверждает брони и управляет столиками и пользователями.

## Возможности

### Клиент
- Регистрация и вход (JWT-авторизация)
- Просмотр столиков на визуальной карте зала
- Выбор даты, времени и количества гостей
- Создание и отмена брони
- Личный кабинет со списком своих броней
- Светлая и тёмная темы

### Администратор
- Управление столиками: добавление, редактирование, отключение, удаление
- Просмотр всех броней, подтверждение и отклонение
- Календарь загрузки зала на 14 дней
- Управление пользователями: блокировка, смена роли

### Безопасность и логика
- JWT-авторизация, пароли хранятся через `bcrypt`
- Проверка пересечений броней по времени
- Запрет бронирования в прошлом
- Запрет удаления столика с активными бронями
- Защита от разжалования последнего администратора
- Единый обработчик ошибок и логирование

## Стек

- Python 3.11+ (проверено на 3.12)
- FastAPI + Uvicorn
- SQLAlchemy 2.0 + SQLite
- Pydantic v2 + pydantic-settings
- python-jose + bcrypt
- Frontend: HTML5, CSS3, Vanilla JavaScript (без сборки)

## Установка

### 1. Клонировать / скачать проект

```bash
git clone <ссылка-на-репозиторий>
cd booking_system
```

Или просто распаковать папку проекта.

### 2. Создать виртуальное окружение

Из корня проекта:

```bash
python -m venv venv
```

### 3. Активировать venv

**Windows (PowerShell):**
```powershell
venv\Scripts\Activate.ps1
```

Если PowerShell ругается на политику запуска скриптов:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

**Windows (cmd):**
```cmd
venv\Scripts\activate.bat
```

**macOS / Linux:**
```bash
source venv/bin/activate
```

В начале строки терминала появится `(venv)`.

### 4. Установить зависимости

```bash
cd backend
pip install -r requirements.txt
```

### 5. Создать файл `.env` в папке `backend/`

Скопируйте `.env.example` → `.env`:

```bash
cp .env.example .env
```

Или создайте вручную. Содержимое:

```env
DATABASE_URL=sqlite:///./booking.db
SECRET_KEY=
ACCESS_TOKEN_EXPIRE_MINUTES=1440
CORS_ORIGINS=*

ADMIN_USERNAME=admin
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=Admin123!ChangeMe
```

**Сгенерировать `SECRET_KEY`:**

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Скопируйте вывод и вставьте в `.env` вместо `сюда_свой_ключ`.

## Запуск

Из папки `backend/` с активированным venv:

```bash
python run.py
```

Или через uvicorn напрямую:

```bash
uvicorn app.main:app --reload --port 8000
```

Сервер стартует на **http://127.0.0.1:8000/**

При **первом запуске** автоматически создаются:
- администратор из настроек `.env` (`admin` / `Admin123!ChangeMe` по умолчанию)
- 4 демонстрационных столика

## API

### Авторизация

| Метод | Путь | Что делает | Доступ |
|---|---|---|---|
| POST | `/api/auth/register` | регистрация клиента | публичный |
| POST | `/api/auth/login` | вход, выдача JWT | публичный |
| GET  | `/api/auth/me` | данные текущего пользователя | авторизован |

### Столики

| Метод | Путь | Что делает | Доступ |
|---|---|---|---|
| GET    | `/api/tables/` | список столиков | публичный |
| POST   | `/api/tables/` | создать столик | админ |
| PUT    | `/api/tables/{id}` | редактировать | админ |
| DELETE | `/api/tables/{id}` | удалить | админ |

### Брони

| Метод | Путь | Что делает | Доступ |
|---|---|---|---|
| GET  | `/api/bookings/my` | мои брони | авторизован |
| GET  | `/api/bookings/` | все брони | админ |
| POST | `/api/bookings/` | создать бронь | авторизован |
| POST | `/api/bookings/{id}/cancel` | отменить бронь | владелец / админ |
| POST | `/api/bookings/{id}/status` | подтвердить / отклонить | админ |
| GET  | `/api/bookings/schedule` | календарь загрузки | админ |
| GET  | `/api/bookings/busy-all?date=YYYY-MM-DD` | занятость всех столов на дату | публичный |
| GET  | `/api/bookings/busy/{table_id}?date=YYYY-MM-DD` | слоты одного стола | публичный |

### Пользователи

| Метод | Путь | Что делает | Доступ |
|---|---|---|---|
| GET  | `/api/users/` | список пользователей | админ |
| POST | `/api/users/{id}/toggle` | блок / разблок | админ |
| POST | `/api/users/{id}/role?role=admin` | сменить роль | админ |

## Правила

- **Пароль:** минимум 6 символов, хотя бы одна буква и одна цифра.
- **Бронирование:** нельзя создавать в прошлом.
- **Пересечения:** нельзя забронировать слот, пересекающийся с активной бронью.
- **Удаление столика:** запрещено, если на нём есть активные брони.
- **Последний админ:** нельзя заблокировать или снять роль.


### Известные нюансы

- `--reload` иногда не подхватывает изменения — перезапускайте сервер вручную.
- Если фронт не подхватывает правки — `Ctrl + Shift + R` (жёсткая перезагрузка).
- Удаление `booking.db` пересоздаёт пустую БД с админом и демо-столиками.
